\begin{abstract}
This paper details the design, implementation, and comparative analysis of multiple calibration models for a temperature measurement system. The system utilizes a PT100 resistance temperature detector (RTD), a high-precision ADS1115 ADC, and an Arduino microcontroller. Two distinct experimental setups are presented. The first employs a Wheatstone bridge, the ADS1115 ADC, and a Least Squares (LSQ) model of the form $V = f(T)$ on a low-voltage dataset. The second experiment, using a simpler circuit and the Arduino's internal 10-bit ADC, compares a Stochastic Gradient Descent (SGD) model and an Inverse LSQ model, both of the form $T = f(V)$, on a high-voltage dataset. The models are validated against unseen data, and their performance is compared to determine the most effective calibration strategy.
\end{abstract}

\section{Introduction}
Accurate temperature measurement is critical in various scientific and industrial applications. While many sensors exist, platinum resistance thermometers like the PT100 offer high accuracy and stability. However, their small resistance change necessitates precise measurement techniques. This project explores two hardware and three software approaches to this problem.

The first experiment (Exp. 1) aims for maximum hardware precision by using a Wheatstone bridge to linearize the sensor response and a 16-bit ADS1115 ADC to capture the small signal. A quadratic model of the form $V = f(T)$ is then fitted.

The second experiment (Exp. 2) tests a simpler, more software-centric approach. It uses a simpler circuit with the Arduino's internal 10-bit ADC and applies more advanced machine learning models (SGD and Inverse LSQ) of the form $T = f(V)$ to achieve high accuracy from simpler hardware. This paper presents both hardware setups, their respective software, and a comparative analysis of all three mathematical models.

\subsection{Role of the ADS1115 ADC}
The ADS1115 is a high-precision, 16-bit Analog-to-Digital Converter.
\begin{itemize}
    \item \textbf{High Resolution}: The 16-bit (65,536 steps) ADS1115 detects the microvolt-level changes from the bridge, which the Arduino's 10-bit (1,024 steps) ADC would miss.
    \item \textbf{Differential Measurement}: The code reads the voltage difference between bridge output terminals (A0 and A1). This \texttt{ads.readADC\_Differential\_0\_1()} function is crucial for rejecting common-mode noise.
    \item \textbf{Programmable Gain}: The code sets the internal amplifier gain to 8x (\texttt{GAIN\_EIGHT}) using \texttt{ads.setGain()}, amplifying the small signal to use more of the ADC's range.
\end{itemize}

\subsection{Software \& Modeling (Exp. 1)}
The Arduino code (`code.cpp`, Listing \ref{lst:arduino_code_exp1}) implements the model derived from `lsq.py`. This model is a quadratic fit of the form $V = aT^2 + bT + c$, based on the training data in Table \ref{table:training_data_exp1}.

The derived coefficients are:
\begin{itemize}
    \item $a = 1.7826 \times 10^{-5}$
    \item $b = 1.4987 \times 10^{-3}$
    \item $c = 0.1570$
\end{itemize}

To convert the measured voltage ($V$) back to temperature ($T$), the Arduino code solves the quadratic formula:
\\[10pt]
$T = \frac{-b + \sqrt{b^2 - 4a(c - V)}}{2a}$
\\[10pt]

This model was validated against a separate dataset (Table \ref{table:validation_data_exp1}), with results in Table \ref{table:validation_results_exp1}.

\subsection{Model 2: Stochastic Gradient Descent (SGD)}
This approach employs a two-part machine learning workflow. First, an offline training script (\texttt{model\_trainer.py}) uses a 2nd-degree polynomial feature set, feature scaling, and a Stochastic Gradient Descent Regressor (\texttt{SGDRegressor}) to learn a baseline model from a static dataset. The complete processing pipeline (polynomial transformer, scaler, and model) is then persisted using \texttt{joblib}.

This method uses \texttt{PolynomialFeatures} to create $V$ and $V^2$ terms, and \texttt{StandardScaler} to normalize these features. Normalization ensures that all features contribute appropriately to the gradient descent, leading to a more stable model. The resulting equation, while complex, is implemented directly on the Arduino (Listing \ref{lst:arduino_code_sgd}). A key feature of this method is the ability to use \texttt{partial\_fit} for "online learning," allowing the model to adapt to new data in real-time and compensate for sensor drift, a significant advantage over static calibration methods.

\subsection{Model 3: Inverse Least Squares}
As a direct comparison to the SGD model, a standard LSQ regression was performed on the same high-voltage dataset, but with the model inverted to $T = aV^2 + bV + c$. This provides a direct, non-scaled polynomial fit. The coefficients found are:
\begin{itemize}
    \item $a \approx 269.84$
    \item $b \approx -953.11$
    \item $c \approx 874.19$
\end{itemize}

\section{Conclusion and Final Recommendation}
This paper successfully designed and tested a PT100-based thermometer using two different hardware setups and three calibration models.

\begin{itemize}
    \item \textbf{Model 1 (LSQ `V=f(T)`):} This model, paired with the ADS1115 and Wheatstone bridge, is hardware-intensive but precise. It requires solving a quadratic equation on the microcontroller.
    \item \textbf{Model 2 (SGD `T=f(V)`):} This model, paired with the internal ADC, is complex to derive (requiring a ML pipeline) but results in a simple (though long) equation on the Arduino.
    \item \textbf{Model 3 (Inverse LSQ `T=f(V)`):} This model uses the same simple hardware as Model 2 but is the simplest to derive and implement, providing a direct $T = aV^2 + bV + c$ formula.
\end{itemize}

Conclusion: Comparing the validation results from Experiment 2 (Tables \ref{table:sgd_results} and \ref{table:inverse_lsq_results}), both the SGD and Inverse LSQ models perform exceptionally well, with predictions very close to the actual temperatures. The **Inverse Least Squares model (Model 3) is arguably the best method**, as it provides nearly identical accuracy to the complex SGD pipeline while being far simpler to calculate, debug, and implement.

The hardware from Experiment 1 (Wheatstone bridge + ADS1115) is the most robust and accurate.

Therefore, the optimal system would be a combination of the superior hardware from Experiment 1 (Wheatstone bridge, ADS1115) and the simpler, direct modeling approach from Experiment 2 (an Inverse LSQ model trained on the low-voltage data).
