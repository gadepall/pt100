\begin{abstract}
This report details the calibration of a PT100 RTD sensor by comparing two hardware setups (a simple voltage divider and a Wheatstone bridge with an ADS1115 ADC).
We first analyze the suitability of a quadratic LSQ model for both setups.
We then compare the accuracy of three different models for the superior Wheatstone bridge data: the LSQ quadratic, an SGD-trained model, and a non-linear Rational model ($V=f(T)$).
The coefficients, equations, and validation accuracy for each model are presented.
\end{abstract}

\section{Introduction}
Accurately measuring temperature with a PT100 sensor requires a precise calibration model to convert its resistance (or a corresponding voltage) to temperature.
This project analyzes different hardware and software models to find an optimal solution.

\section{Hardware Setup}
Two main analog front-ends were tested.
\begin{itemize}
    \item \textbf{Setup 1:} A Wheatstone bridge with an external 16-bit ADS1115 ADC.
\item \textbf{Setup 2:} A simple voltage divider with the Arduino's internal 10-bit ADC.
\end{itemize}
Component lists and connection diagrams are provided in the appendix tables.

\section{Models Used}
This report details the development and evaluation of several regression models for predicting sensor output based on input values. Specifically, we focus on two scenarios: predicting temperature from voltage using a Wheatstone bridge with ADC, and predicting resistance from voltage using a voltage divider without ADC. We investigate Random Forest Regressor, Inverse Quadratic Least Squares (LSQ) for both Wheatstone and Voltage Divider setups, and a Stochastic Gradient Descent (SGD) Regressor.

\section{Model Evaluation and Comparison}

This section presents the evaluation of the trained models and a comparison of their performance based on Mean Squared Error (MSE) and R-squared (R2) metrics.

\subsection{Model Explanations}

\subsubsection{Random Forest Regressor (Wheatstone with ADC)}
The Random Forest Regressor is an ensemble learning method that constructs a multitude of decision trees during training. For regression tasks, it averages the predictions of individual trees to produce a more stable and accurate prediction. This model was applied to the Wheatstone bridge dataset, where the goal was to predict temperature (Y) from voltage (X) directly, leveraging its ability to capture complex non-linear relationships without explicit feature engineering of the target variable.

\subsubsection{Inverse LSQ (Quadratic) for Wheatstone with ADC}
This model approaches the Wheatstone bridge problem by fitting a quadratic equation of the form \(X = aY^2 + bY + c\), where Y is temperature and X is voltage. The coefficients \(a\), \(b\), and \(c\) are determined through linear least squares regression.
The fitted equation for the Wheatstone bridge is:
\[ X = -0.000006742Y^2 + 0.004346059Y + 0.055941163 \]
To predict Y from a given X, we rearrange the equation into a standard quadratic form: \(aY^2 + bY + (c - X) = 0\).
The solution for Y is then given by the quadratic formula, taking the positive root:
\[ Y = \frac{{-b \pm \sqrt{{b^2 - 4a(c - X)}}}}{{2a}} \]
This method assumes an underlying quadratic relationship between voltage and temperature, and its performance depends on how well this assumption holds for the given data.

\subsubsection{Inverse LSQ (Quadratic) for Voltage Divider without ADC}
Similar to the Wheatstone LSQ model, this model also uses a quadratic inverse approach. It models the relationship between resistance (Y) and voltage (X) from the voltage divider circuit as \(X = aY^2 + bY + c\).
The fitted equation for the Voltage Divider is:
\[ X = -0.000014990Y^2 + 0.005589496Y + 2.526066163 \]
The coefficients are determined through linear least squares regression, and then the model predicts resistance (Y) from measured voltage (X) using the positive root of the quadratic equation:
\[ Y = \frac{{-b \pm \sqrt{{b^2 - 4a(c - X)}}}}{{2a}} \]
This method is suitable for circuits where the voltage-resistance relationship can be approximated quadratically.

\subsubsection{Stochastic Gradient Descent (SGD) Regressor (Wheatstone with ADC)}
The SGD Regressor is a linear model trained with Stochastic Gradient Descent, which is an efficient optimization algorithm. This model was applied to the Wheatstone bridge data. Due to its sensitivity to feature scaling, both the input features (X) and the target variable (Y) were scaled using StandardScaler before training. The predictions were then inverse-transformed back to the original scale for evaluation.

\subsection{Model Comparison and Conclusion}

Comparing the performance metrics, the Random Forest Regressor, the Inverse LSQ (Quadratic) model for the Wheatstone bridge with ADC data, and the SGD Regressor (after scaling) all achieved exceptionally high R-squared scores (approximately 0.999 to 0.9999) and very low Mean Squared Error (MSE) values (approximately 0.0000). This indicates that these three models are highly accurate in predicting temperature from voltage for this specific Wheatstone setup.

The Inverse LSQ (Quadratic) model for the Voltage Divider without ADC also showed a strong performance with an R-squared of 0.9977, but its MSE of 0.6612 is significantly higher than the models for the Wheatstone bridge. This suggests that while the quadratic relationship generally holds, the predictions for the voltage divider might have slightly more error compared to the Wheatstone bridge models.

Based on the Mean Squared Error (MSE), the best performing models are the \textbf{Inverse LSQ (Quadratic) model for Wheatstone with ADC} and the \textbf{Random Forest Regressor (Wheatstone with ADC)} with an MSE of 0.0128 and 0.0053 respectively. Both are closely followed by the SGD Regressor for Wheatstone with ADC. The minimal difference in performance among these three indicates all are highly suitable for the Wheatstone bridge, but the LSQ model might offer a simpler deployment due to its explicit functional form. The SGD Regressor also performs commendably, especially considering its linear nature, after proper data scaling.

\section*{Appendix - Data Collection Using Optical Character Recognition (OCR)}

This project utilizes an auxiliary script for \textbf{automated data collection} by employing Computer Vision and Optical Character Recognition (OCR) to capture paired voltage and temperature readings from physical displays.

\subsection{Script Description: The Auto Trainer}
This Python script is designed to capture video from a webcam, identify and read text from two specific screen regions (voltage and temperature), and log the data. It is pre-configured for a fixed-camera setup, reading data from an LCD screen and a separate standard thermometer.

\subsubsection{Prerequisites and Setup}
\begin{itemize}
    \item \textbf{Hardware:} A stable webcam connection. An NVIDIA GPU with CUDA is optional but recommended for faster processing (script defaults to $\text{gpu}=\text{True}$).
    \item \textbf{Software:} Python 3.x with the libraries $\texttt{opencv-python}$, $\texttt{easyocr}$, and $\texttt{numpy}$. The $\texttt{img/}$ folder must be created in the script directory for saving debug images.
\end{itemize}

\subsubsection{Calibration Requirement}
The script requires calibration to match the specific camera, lighting, and display setup. The critical sections to modify are:
\begin{itemize}
    \item \textbf{GPU Usage:} Set $\texttt{gpu}=\text{False}$ if an NVIDIA GPU is unavailable.
    \item \textbf{Frame Cropping:} The regions of interest for voltage and temperature must be precisely defined using Python slicing in the format $\texttt{[y1:y2, x1:x2]}$.
    \item \textbf{Image Processing:} Values for $\texttt{cv2.threshold}$ (e.g., $130$), kernel size in $\texttt{cv2.getStructuringElement}$, and Gaussian blur kernel size must be adjusted to ensure clear and solid text for the OCR engine.
\end{itemize}

\subsection{Data Collection Methodology}
The dataset is collected by simulating a controlled \textbf{cooling cycle} to capture paired readings.
\begin{enumerate}
    \item \textbf{Setup:} The PT100 probe and a reference thermometer are placed in an electric kettle filled with water.
    \item \textbf{Heating Phase:} The water is heated to boiling.
    \item \textbf{Recording Phase:} Upon reaching boiling, the kettle is switched off, and a video is recorded, ensuring both the PT100's LCD display and the reference thermometer are visible.
    \item \textbf{Cooling Phase:} The video captures the natural temperature drop.
    \item \textbf{Data Extraction:} Frames are extracted from the video, and OCR is applied to detect the voltage and temperature readings.
\end{enumerate}

\subsection{Output Format}
The script generates two outputs for debugging and data logging:
\begin{itemize}
    \item $\texttt{out.txt}$: A log file where every $15$ frames, a new line is added with the format $\texttt{[voltage\_reading] [temperature\_reading]}$ if both readings are successfully detected.
    \item $\texttt{img/}$ Directory: This folder saves debug images ($\texttt{voltageXX.png}$ and $\texttt{tempXX.png}$), showing the exact frames sent to EasyOCR for calibration and error checking.
\end{itemize}
